# 环境搭建指引

> 目标：在 Windows 上搭好 FE8 改版开发环境（WSL2 Ubuntu + arm-none-eabi 工具链 + 框架 + 中文版 ROM）。
> 预计耗时：脚本执行约 20 分钟 + 重启一次。磁盘需求约 5 GB。

---

## 为什么需要 WSL

`fireemblem8-expansion` 的官方一键安装脚本（`scripts/quickstart.sh`）只支持 **Ubuntu / WSL / Arch / macOS**，**不含原生 Windows**。WSL2 是 Windows 下的唯一顺畅路径。

---

## 三个脚本

| 脚本 | 在哪运行 | 作用 |
|---|---|---|
| `1-install-wsl.ps1` | Windows（管理员 PowerShell） | 安装 WSL2 + Ubuntu（标准路径） |
| `4-install-wsl-manual.ps1` | Windows（管理员 PowerShell） | **完全绕开 Microsoft Store 的手动安装**——`wsl --install` 报 403 或极慢时用这个 |
| `5-fix-virtualization.ps1` | Windows（管理员 PowerShell） | **虚拟化层诊断与修复**——报 `HCS_E_SERVICE_NOT_AVAILABLE` / `vmcompute` 缺失 / `HypervisorPresent=False` 时用 |
| `2-setup-project.sh` | WSL Ubuntu 内 | 克隆框架 + 装依赖 + 构建 + 出中文版 |
| `3-verify-env.sh` | WSL Ubuntu 内 | 自检环境是否就绪 |

## 步骤

### 第一步：安装 WSL2 + Ubuntu

> **右键菜单里没有"使用 PowerShell 运行"怎么办？**
> 新版 Windows 常把该选项藏起来。改用下面任一方式打开**管理员** PowerShell：
>
> - **Win + X** → 选「终端(管理员)」或「Windows PowerShell (管理员)」
> - 开始菜单搜索 `powershell` → 右键结果 → 「以管理员身份运行」
> - **Win + R** → 输入 `powershell` → 按 **Ctrl + Shift + Enter**
>
> 然后在管理员 PowerShell 里执行：
> ```
> powershell -ExecutionPolicy Bypass -File "D:\workbuddy\FireEmblem Realm-in-Ashes\tools\1-install-wsl.ps1"
> ```

**方式 A：跑脚本（推荐）**

1. 用上面任一方式打开管理员 PowerShell
2. 执行上面的命令
3. 脚本会：检查权限与系统版本 → 检查现有 WSL → 启用 WSL / 虚拟机平台功能 → 安装 Ubuntu
4. 看到 "下一步：重启电脑" 后，**重启 Windows**

**方式 B：手敲命令（不想跑脚本）**

管理员 PowerShell 里逐条执行：

```powershell
wsl --install -d Ubuntu --no-launch --web-download
Restart-Computer
```

> **`--web-download` 是关键参数**：不加它时 WSL 从 Microsoft Store 渠道下载，中国大陆网络下常见两种失败——`已禁止(403)`（走代理时商店接口拒绝代理 IP）或极慢（不走代理时直连）。加上它改为**从 GitHub Releases 下载**，代理可用时速度正常。

若上面报错（提示未启用功能），改用底层命令：

```powershell
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
# 重启后
wsl --install -d Ubuntu --no-launch --web-download
```

**重启后**：Ubuntu 会自动弹出要求设置
- 用户名：建议全小写英文，如 `shanhe`
- 密码：输入时**不显示任何字符**，这是正常的，输完回车即可

**如何确认装好了**：在任意终端执行 `wsl -d Ubuntu`，能进入 `用户名@机器名:~$` 提示符即成功。

### 第二步：搭建项目环境

进入 WSL：在 Windows 终端里执行 `wsl -d Ubuntu`（如果是用 `4-install-wsl-manual.ps1` 或手动导入装的，发行版名可能是 `Ubuntu-24.04`，用 `wsl -l -v` 查实际名字），然后：

```bash
# 推荐：先把脚本拷进 WSL（避免在 /mnt 下操作）
cp "/mnt/d/workbuddy/FireEmblem Realm-in-Ashes/tools/2-setup-project.sh" ~/
chmod +x ~/2-setup-project.sh
bash ~/2-setup-project.sh
```

脚本会自动：
1. 环境自检（权限、磁盘）
2. 克隆框架到 `~/projects/fireemblem8-expansion`
3. `sudo apt install` 装齐依赖（会要你输入 WSL 密码）
4. 首次构建（最长约 15 分钟）
5. 构建中文版（32M ROM）

### 第三步：自检

```bash
cp "/mnt/d/workbuddy/FireEmblem Realm-in-Ashes/tools/3-verify-env.sh" ~/
bash ~/3-verify-env.sh
```

全绿且没有 ✗ 即表示环境就绪。

### 第四步：让 WSL 走代理（中国大陆环境必读）

> **好消息：`2-setup-project.sh` 已内置自动配置**——它会先试直连，不行就依次探测 `127.0.0.1:7897`（镜像网络）与网关地址（NAT 模式），命中后自动写入 `~/.bashrc` 并配置 apt 代理。一般不用你手动做这一步。
> 端口不是 7897 时：`CLASH_PORT=你的端口 bash 2-setup-project.sh`

WSL 里的 `apt install` 和 `git clone` 都走 Linux 自己的网络栈，**默认不吃 Windows 的 Clash 代理**。不配的话依赖安装会非常慢甚至失败。

**方案一：镜像网络模式（推荐，Win11 22H2+ 可用）**

让 WSL 直接共用 Windows 的网络栈，Clash 的系统代理/TUN 就都自动生效了。

在 Windows 侧新建 `C:\Users\<你的用户名>\.wslconfig`：

```ini
[wsl2]
networkingMode=mirrored
```

然后重启 WSL：

```powershell
wsl --shutdown
```

> ⚠️ **改完 `.wslconfig` 必须执行 `wsl --shutdown`，否则改动不会加载。**
> 实测教训：只改文件不 shutdown，会话仍沿用旧的 NAT 网络栈，此时 `127.0.0.1:7897` 指向的是 Ubuntu 自己而不是 Windows 上的 Clash，`curl` 会**无限期挂起**（没有任何报错，看起来像"卡死"）。排查方法：给 curl 加 `--max-time 8`，不通就会明确报错而不是挂死。
>
> 另外，`wsl --shutdown` 后建议用 `wsl -d Ubuntu-24.04 --cd ~` 进入，否则会继承启动时所在目录（常见是 `/mnt/c/WINDOWS/system32`，在那个目录里跑诊断命令容易受权限与路径影响）。

（下次进 `wsl -d Ubuntu` 生效）

**方案二：手动指定代理（通用）**

1. 在 Clash 里打开**「允许局域网连接」**（Allow LAN）
2. 在 Clash 设置里记下**混合端口**（Clash Verge 常见 `7897`，CFW 常见 `7890`）
3. 进 WSL 后执行（把端口换成实际的）：

```bash
# 拿到 Windows 宿主 IP（NAT 模式下是默认网关）
export HOST_IP=$(ip route show default | awk '{print $3}')
export http_proxy="http://$HOST_IP:7897"
export https_proxy="http://$HOST_IP:7897"

# 验证（务必加 --max-time，不通时明确报错而不是挂死）
curl -I --max-time 8 https://github.com
```

要长期生效，写进 `~/.bashrc`：

```bash
cat >> ~/.bashrc <<'EOF'
export HOST_IP=$(ip route show default | awk '{print $3}')
export http_proxy="http://$HOST_IP:7897"
export https_proxy="http://$HOST_IP:7897"
EOF
```

**apt 单独配**（`sudo` 不继承用户环境变量）：

```bash
sudo tee /etc/apt/apt.conf.d/95proxy > /dev/null <<'EOF'
Acquire::http::Proxy "__PROXY__";
Acquire::https::Proxy "__PROXY__";
EOF
# 把 __PROXY__ 替换成实际值，例如 http://172.20.16.1:7897
sudo sed -i "s|__PROXY__|http://$(ip route show default | awk '{print $3}'):7897|g" /etc/apt/apt.conf.d/95proxy
```

**方案三（推荐）：apt 换清华源 + 让 apt 不走代理**

实测中，**apt 走代理是 404 的高发源头**。原因是 Clash 的 Fake-IP 机制会返回 `198.18.x.x` 段地址把 `ubuntu.com` 劫持到代理节点，而节点上的镜像缓存一旦过期，包索引里记录的版本在源上已不存在，就会报：

```
E: Failed to fetch http://security.ubuntu.com/ubuntu/pool/main/e/expat/libexpat1_2.6.1-2ubuntu0.6_amd64.deb  404  Not Found [IP: 198.18.0.59 80]
```

**看到 `[IP: 198.18.x.x]` 就基本可以确定是 Fake-IP 劫持。** 解法是让 apt 直接走国内镜像：

```bash
# 1) 撤掉 apt 的代理（否则清华源也会被劫持）
sudo rm -f /etc/apt/apt.conf.d/95proxy

# 2) 换成清华源（Ubuntu 24.04 用新格式 ubuntu.sources）
sudo tee /etc/apt/sources.list.d/ubuntu.sources > /dev/null <<'EOF'
Types: deb
URIs: https://mirrors.tuna.tsinghua.edu.cn/ubuntu
Suites: noble noble-updates noble-backports
Components: main restricted universe multiverse
Signed-By: /usr/share/keyrings/ubuntu-archive-keyring.gpg

Types: deb
URIs: https://mirrors.tuna.tsinghua.edu.cn/ubuntu
Suites: noble-security
Components: main restricted universe multiverse
Signed-By: /usr/share/keyrings/ubuntu-archive-keyring.gpg
EOF

# 3) 让国内镜像域名绕过代理
export no_proxy="mirrors.tuna.tsinghua.edu.cn,mirrors.aliyun.com,localhost,127.0.0.1"
export NO_PROXY="$no_proxy"

# 4) 更新并安装
sudo apt-get update
sudo apt-get install -y --fix-missing build-essential git \
  gcc-arm-none-eabi binutils-arm-none-eabi libnewlib-arm-none-eabi gdb-multiarch \
  pkg-config libpng-dev python3 python3-pip python3-numpy python3-pil
```

> 注意：**`git clone` 仍需代理**（GitHub 在国内直连不可用），所以 `no_proxy` 只放行国内镜像域名，不要把 `github.com` 加进去。

> **Clash 节点选择建议**：优先用**中国香港 / 新加坡**节点访问 GitHub 和 apt 源；日本节点在部分线路下连接微软/GitHub 会被拒（实测 403）。

## 搭建完成后怎么玩

**Windows 侧访问 WSL 文件：** 在资源管理器地址栏输入

```
\\wsl$\Ubuntu\home\<你的用户名>\projects\fireemblem8-expansion\build\
```

用 **mGBA** 打开里面的 `.gba` 文件。

**推荐开发方式：** 装 VS Code + **WSL 扩展** → `Ctrl+Shift+P` → "WSL: Connect to WSL" → 打开 `~/projects/fireemblem8-expansion`。代码在 Windows 界面里改，编译在 WSL 终端里跑，体验和本地开发无差别。

## 重要注意事项

### 仓库必须放在 WSL 文件系统内

**不要**放在 `/mnt/c/` 或 `/mnt/d/` 下。跨文件系统访问会让构建慢十倍以上，且文件权限/符号链接行为异常。文档可以放 `D:\workbuddy\`，但**代码仓库必须在 WSL 内**（`~/projects/`）。

### 中文版必须 32M ROM

带真实 locale 的构建用 16M 会在编译前直接失败。脚本已经写死 `--with-rom-size=32M`。

### 首次构建慢是正常的

约 2.5 GB 编译产物，最长达 15 分钟。后续增量构建会快很多。

## 常见问题

| 症状 | 处理 |
|---|---|
| **右键没有「使用 PowerShell 运行」** | 用 Win+X → 「终端(管理员)」，或 Win+R → `powershell` → Ctrl+Shift+Enter |
| **怎么确认窗口是管理员？** | 看**标题栏**：有「管理员:」前缀才是。`C:\WINDOWS\system32` 这个路径不代表管理员权限 |
| **怎么判断 WSL 到底装没装？** | 看 `C:\Program Files\WSL\wsl.exe` 是否存在（存在=装好）；`C:\Windows\System32\wsl.exe` 只是 Windows 自带存根，**≠ 已安装** |
| **脚本报乱码错误 "wsl.exe : *g塠艌?u嶯 Linux..."** | 这是旧版脚本的 bug（已修）。乱码解码后是「未安装用于 Linux 的 Windows 子系统」。直接用方式 B 手敲命令即可 |
| **`wsl --install` 报「已禁止(403)」** | 走了代理访问 Microsoft Store 接口，被拒。**改用 `--web-download` 从 GitHub 下载**，或用 `4-install-wsl-manual.ps1` |
| **导入发行版报 `HCS_E_SERVICE_NOT_AVAILABLE`** | **运行时先用 `5-fix-virtualization.ps1` 诊断**。判定标准不是"待重启标记"，而是**功能性判据**：`System32\vmcompute.exe` 在盘上 + `vmcompute` 服务存在 + `HypervisorPresent=True`。三者不满足就是虚拟化层没起来 |
| **功能显示「已启用」但就是不行（Win11 家庭版高频）** | 用 `Test-Path C:\Windows\System32\vmcompute.exe` 确认。**如果这个文件缺失**，说明功能状态虽"已启用"、FOD（按需功能）负载却没装上 → 必然报 HCS 错误。**官方建议：先把 Windows 更新全部装完，再启用虚拟机平台** |
| **重启后仍报 HCS / `vmcompute` 仍缺失** | 按优先级：① 设置 → Windows 更新 → 装完所有更新 → 重启（**首选**）② 检查网络能否连到 Microsoft ③ `5-fix-virtualization.ps1 -RepairImage` 修组件存储（10~30 分钟）④ `-Toggle` 禁用+重启用虚拟机平台 |
| **待重启标记一直甩不掉** | `RebootPending` 可能被 Windows 更新单独置位并长期滞留，**不等于**虚拟化没生效。以 `vmcompute.exe` + `vmcompute` 服务 + `HypervisorPresent` 为准 |
| **脚本报「CPU 虚拟化在 BIOS 中被禁用」但实际是好的** | **WMI 已知陷阱**：一旦 hypervisor 运行（`HypervisorPresent=True`），`Win32_Processor` 的 `VirtualizationFirmwareEnabled` 与 `SecondLevelAddressTranslationExtensions` 都会变成 `False`——因为 VT-x 已被 hypervisor 接管，WMI 不再暴露该能力位。**以 `HypervisorPresent` 为准**，不要据这两个字段判断 BIOS |
| **`wsl --install` 下载极慢（几 KB/s）** | 说明没走代理在直连。开代理后加 `--web-download`；或直接手动下载 MSI（见下） |
| **`请求的操作需要提升`** | 当前 PowerShell 不是管理员。用 Win+X →「终端(管理员)」 |
| **Clash TUN/虚拟网卡模式一开就 403，关掉又很慢** | 403 来自商店接口拒绝代理 IP 段，不是网速问题。**TUN 开着 + 加 `--web-download`**（改走 GitHub）即可兼顾 |
| 脚本说「需要管理员权限」 | 必须用管理员身份运行；普通 PowerShell 窗口不行 |
| `wsl --install` 报错说需要更新 | 执行 `wsl --update`（需管理员），或加 `--web-download` |
| `wsl --install` 返回非零 | 先跑 dism 启用两个功能，重启后再装 |
| apt 安装失败 | 需要 sudo 权限；脚本会停下提示 |
| **WSL 里 apt / git 特别慢** | WSL 不走 Windows 代理，见「第四步：让 WSL 走代理」。注意 `git clone`（GitHub）需要走代理，而 apt 建议走国内源直连，两者策略相反 |
| **apt 报 404，地址里带 `[IP: 198.18.x.x]`** | **Clash Fake-IP 劫持**（`198.18.0.0/15` 是 Clash 保留段）。代理节点上的镜像缓存过期 → 索引里的包版本在源上已不存在。**解法：撤掉 apt 代理 + 换清华源**，见「第四步 · 方案三」 |
| **改完 `.wslconfig` 但代理还是不通 / curl 无限挂住** | **忘了 `wsl --shutdown`**。不 shutdown 会沿用旧网络栈，`127.0.0.1:7897` 指向 Ubuntu 自己而非 Clash。诊断命令一律加 `curl --max-time 8`，不通会明确报错而不是挂死 |
| **进 WSL 后所在目录是 `/mnt/c/WINDOWS/system32`** | 从该目录启动 wsl 的副作用。用 `wsl -d Ubuntu-24.04 --cd ~` 进入，别在 `system32` 里干活 |
| **`/mnt/d` 下的脚本 `cp` 报 No such file** | 路径含中文（`FireEmblem Realm-in-Ashes`）与空格，WSL 侧转义易出错。**优先用 `tools/wsl/` 下的纯 ASCII 副本** |
| **脚本打印 `\033[0;32m` 这种字面量** | 旧版 bug（已修）：bash 里 `'\033[0;32m'` 是字面量，必须写 `$'\033[0;32m'` 才是真的 ESC 字节 |
| **脚本说「环境搭建完成」但 make 其实失败了** | 旧版 bug（已修）：原脚本无条件打印成功。现改为三项齐备（默认 make、中文版 make、产物存在）才报成功，否则 exit 1 并打印排查命令 |
| arm-none-eabi-gcc 找不到 | `sudo apt install gcc-arm-none-eabi` |
| 缺少 gdb-multiarch | `sudo apt install gdb-multiarch` |
| 缺少 mgba | 非构建必需。`sudo apt install mgba-sdl`；或直接在 Windows 侧用 mGBA 打开 `.gba` |
| 构建报内存/预算溢出 | 这是 GBA 的真实约束，看 `5.改版工程手册.md` §5.3 |
| 构建特别慢 | 检查仓库是否在 `/mnt/` 下；确认 `-j$(nproc)` 生效 |
| WSL 磁盘占用过大 | 构建产物在 `~/projects/fireemblem8-expansion/build/`，可 `make clean` |
| **构建失败但看不出原因** | **先跑 `bash ~/6-diagnose-build.sh`** 一次性体检。全量日志在 `~/shanhe-logs/build-<时间戳>.log` |
| **报 `can't open tools/gbagfx/gbagfx.s for reading`** | **子模块未初始化**（最高频根因）。`git clone --recursive` 在国内网络下会**静默失败**——主仓库成功就往下走了。修复见下 |

### 完全绕开 `wsl --install` 的手动装法（推荐给国内网络）

如果 `wsl --install` 反复报 403 或慢得无法接受，**直接用 `4-install-wsl-manual.ps1`**，它全程不碰 Microsoft Store：

```powershell
powershell -ExecutionPolicy Bypass -File "D:\workbuddy\FireEmblem Realm-in-Ashes\tools\4-install-wsl-manual.ps1"
```

脚本做的事：

| 步骤 | 内容 |
|---|---|
| 自动提权 | 非管理员会自己弹 UAC 重启自己 |
| WSL 本体 | 从 GitHub Releases 下 `wsl.2.7.14.0.x64.msi`（247 MB），**校验 SHA256** 后安装 |
| Ubuntu 镜像 | 从**清华镜像**自动选最新 `ubuntu-24.04.x-wsl-amd64.wsl`（约 371 MB，国内直连快，无需代理）；失败则回退官方 cloud-images |
| 导入发行版 | `wsl --import` 到指定目录（默认 `D:\WSL\Ubuntu-24.04`），可用空间可自选盘 |
| 建用户 | 建 Linux 用户 + 加入 sudo + 写入 `/etc/wsl.conf` 设为默认，并引导设密码 |

常用参数：

```powershell
# 自定义发行版名 / 安装目录 / 用户名
powershell -ExecutionPolicy Bypass -File "...\4-install-wsl-manual.ps1" `
  -DistroName Ubuntu-24.04 -InstallDir D:\WSL\Ubuntu-24.04 -UserName shanhe

# WSL 本体已装好，只补发行版
powershell -ExecutionPolicy Bypass -File "...\4-install-wsl-manual.ps1" -SkipWsl

# 只装 WSL 本体，不装发行版
powershell -ExecutionPolicy Bypass -File "...\4-install-wsl-manual.ps1" -SkipUbuntu
```

**纯手动等价步骤**（不想跑脚本时）：

1. WSL 本体：浏览器打开 https://github.com/microsoft/WSL/releases/latest
   下载 `wsl.<版本>.0.x64.msi` → 双击安装
2. Ubuntu 镜像：浏览器打开 https://mirrors.tuna.tsinghua.edu.cn/ubuntu-releases/noble/
   下载最新的 `ubuntu-24.04.x-wsl-amd64.wsl`
3. 导入（管理员 PowerShell）：
   ```powershell
   wsl --import Ubuntu-24.04 D:\WSL\Ubuntu-24.04 "$env:USERPROFILE\Downloads\ubuntu-24.04.5-wsl-amd64.wsl" --version 2
   ```
4. 建用户：
   ```powershell
   wsl -d Ubuntu-24.04 -u root
   # 进去后：
   useradd -m -G sudo -s /bin/bash shanhe
   passwd shanhe
   printf '[user]\ndefault=shanhe\n' > /etc/wsl.conf
   exit
   wsl --terminate Ubuntu-24.04
   ```

## 环境就绪后的第一件事

**不是做角色，是先实测中文字库容量**——这是本项目 P0 最高优先级风险（设计文档 §5.1、工程手册 §8）。

框架的 CJK 字体页按字频取舍，示例规模有限，而 20 章剧本文本量可能远超。这件事直接决定项目体量能不能做到 20 章。
