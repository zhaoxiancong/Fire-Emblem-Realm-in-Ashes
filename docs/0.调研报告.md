# 火焰纹章像素版复刻 — 调研报告

> 任务：做一款有完整剧情、尽量还原原版像素风的"属于自己的改版"火焰纹章游戏
> 版本：v0.5
> 调研日期：2026-09-24
> 状态：调研完成（三路调研均已汇总入文）；**路线已拍板见第十一节（2026-09-24）**

## 摘要

复刻童年 GBA 火纹、做一款"完整剧情 + 还原像素风"的自己的游戏，**两条路都走得通**：

- **路线 A：GBA ROM 改版（FEBuilderGBA）**——像素风 100% 原生还原、工具链成熟、中文教程齐全；代价是受 GBA 硬件限制、事件脚本是真编程、法律灰色（只能发补丁）。
- **路线 B：现代引擎做原创 SRPG（首推 SRPG Studio，备选 Godot 4）**——完全合法、可自由发布；SRPG Studio 免编程即可搭出转职/武器克制/支援对话等火纹系统，换 GBA 风素材即可接近原版观感；代价是素材要自己解决，深度定制要写脚本。

**两条路的共同硬投入是"内容"**：剧情写作、像素美术（约占总工时 40~45%，战斗动画是最大时间黑洞）、关卡与数值设计、音乐。单人业余做 15 章体量约 1200~1500 小时（1.5~3 年）；建议先做 3~5 章 demo 验证。

## 一、两条可行路线总览

| | 路线 A：GBA ROM 改版 | 路线 B：现代引擎原创 |
|---|---|---|
| 像素风还原度 | 100%（GBA 引擎原生输出） | 高（换 GBA 风素材可接近原版） |
| 编程量 | 事件脚本（EA） | SRPG Studio 免编程；Godot 需编程 |
| 法律风险 | 灰色地带，只发补丁 | 完全合法，可上 Steam/itch.io |
| 技术天花板 | GBA 硬件（240×160、内存） | 无上限 |
| 主要成本 | 时间（脚本+剧情+美术） | 素材 + 时间 |
| 适合人群 | 对"原汁原味"有执念、能长期投入 | 想合法发布、可能要现代功能 |

两路**共同**需要：剧情/关卡设计、数值平衡、像素美术、音乐、项目管理与长期毅力。

## 二、路线 A：GBA ROM 改版

### 2.1 核心工具：FEBuilderGBA（事实标准）

日本开发者 laqieer 维护的可视化 IDE，整合了散落的老工具，是当前唯一活跃维护的 GBA 火纹改版中心。支持 **FE6《封印之剑》/ FE7《烈火之剑》/ FE8《圣魔之光石》** 三作（FE8 功能最完善）。

覆盖功能：地图编辑、事件脚本（内置汇编器+图形化事件编辑）、文本编辑、人物/职业/物品/武器数据、头像与半身像导入、战斗动画编辑、音乐音效表替换、商店/支援对话，还内置技能系统等现代补丁。自带中文界面，有官方中文 wiki 和 B 站中文入门教程，按日期滚动更新。

- 仓库：https://github.com/FEBuilderGBA/FEBuilderGBA
- 国内镜像发行版：https://gitee.com/laqieer/FEBuilderGBA/releases
- 中文指南：https://laqieer.github.io/dw.ngmansion.xyz/export_xhtml/zh/guide/febuildergba/
- FEU 官方支持帖：https://feuniverse.us/t/fe-builder-gba-if-you-have-any-questions-attach-report7z/2845
- B 站萌新入门视频：https://www.bilibili.com/video/BV1Aq4y1o7As/

### 2.4 法律与实操

- **自备合法 ROM**（自己卡带 dump 或合法购得）是社区前提；**只发补丁、从不发 ROM** 是行规。
- 任天堂对高调粉丝游戏发过 DMCA（AM2R、宝可梦 Uranium）；但 GBA 火纹改版社区运转 20 余年基本未被针对——只发补丁、不商用、低调发布是低风险惯例。
- 中文 ROM 现状：烈火/圣魔完全汉化版现经贴吧网盘、模拟器合集流传，无官方合法渠道；生态仍活跃（2024 年还有《圣魔之光石 Reforged》汉化发布）。

### 2.5 需要的技能与学习路径（估算）

- 入门合计 1~2 个月出第一个带剧情的小改版：
  1. FEBuilderGBA 基础 + 文本/数据编辑 —— 3~7 天
  2. 事件脚本（EA）与过场剧情 —— 2~4 周入门，完整剧情需持续打磨
  3. 地图设计 —— 1~2 周入门
- 进阶：
  4. 头像/半身像导入 —— 工具 1~3 天学会，但像素画功底需数月
  5. 战斗动画导入/自制 —— 导入数天；**自制是最大时间黑洞（单个动画以周计）**
  6. 音乐替换 —— 3~7 天
  7. 现代引擎补丁（技能系统等）—— 数周，可选
- 整体：单人业余做 demo（3~5 章）约 3~6 个月；完整剧情作品约 1~2 年。

### 2.6 真实案例

- **Vision Quest**（FE8，30+ 章完全原创剧情，v3 完成于 2022）——社区公认最强改版之一，证明"原创剧本+原版引擎+单人完成"可行：https://feuniverse.us/t/fe8-complete-fire-emblem-vision-quest-v3-by-pushwall-1-oct-22/3815
- **The Sacred Trilogy**（FE8 重写+原创）：https://feuniverse.us/t/fe8-completed-the-sacred-trilogy-reskin-and-rebalance/5359
- **The Last Promise**（FE7，最早出圈的完整原创剧情改版）
- **圣邪的意志**（国产，FE8 基底原创同人，火花天龙剑/狼组出品）——中文圈代表作

**小结**：优点=工具链成熟一站搞定、20 年社区素材可复用、GBA 引擎原生输出像素风还原度 100%、中英文教程齐全。代价=受 GBA 硬件限制（分辨率 240×160、内存）、事件脚本是真编程工作量巨大、法律灰色地带只能发补丁、自制战斗动画极耗时。适合对童年像素风有执念、能接受一年以上长期投入的人。

## 三、路线 B：现代引擎做原创 SRPG

### 3.1 候选引擎对比

| 维度 | SRPG Studio | Godot 4 | Unity 2D | RPG Maker+SRPG 插件 |
|---|---|---|---|---|
| 学习难度（零基础） | ★ 极低（免编程） | ★★ 中（GDScript） | ★★★ 高（C#） | ★★ 中（插件配置） |
| 金钱成本 | 本体+DLC，几十美元级，常打折 | 0 | 0（年收入<20 万美元） | 本体+插件，几十美元级 |
| 火纹像素风还原度 | ★★★★（默认非像素风，换素材可接近） | ★★★★（全可控，自己搭） | ★★★★（Pixel Perfect） | ★★★（RTP 味重） |
| 自由定制程度 | ★★★（脚本可深改） | ★★★★★（无上限） | ★★★★★（无上限） | ★★（受插件限制） |
| 社区/教程 | ★★★（日文为主，中文渐多） | ★★★★（中英教程多） | ★★★★★（海量但杂） | ★★★（论坛帖为主） |
| 成品可分发性 | ★★★★★（一键导出 exe，可上 Steam） | ★★★★★（多平台导出） | ★★★★★（多平台导出） | ★★★★（桌面/Web） |

### 3.2 各引擎要点

**SRPG Studio（推荐首选）** https://srpgstudio.com/
- 专为火纹式 SRPG 设计：职业转职、武器克制、支援对话、技能、道具、AI、多章剧情全部**免编程可配置**，另有脚本接口可深度定制。
- 注意：默认观感偏"复古混搭"而非纯 GBA 像素（《维斯塔利亚传说》即现代立绘+复古地图）；但素材可全部替换，低分辨率+整数缩放、16×16 tile 放大 2 倍即可做成 GBA 风——像素风同人《卡琳的尤格多拉尔战纪》(Karin's War) 是成功案例（https://feuniverse.us/t/fe4-fe5-fangame-by-srpg-studio-karins-war-legend-on-jugdral-complete/36231/30 ）。
- 2025 年 8 月版本已含**官方简繁中文**；火纹之父加贺昭三正用它开发《维斯塔利亚传说 I/II》，是最强背书。
- 社区脚本 wiki：https://w.atwiki.jp/srpg_studio/ ；民间工具箱 https://github.com/Sinflower/SRPG-ToolBox
- Steam 页面（售价请以此为准）：https://store.steampowered.com/app/857320/SRPG_Studio/

**Godot 4（次选，免费且想学编程）**
- MIT 开源免费；TileMap 原生支持 32×32 网格；240×160 viewport 整数缩放实现 GBA 锐利像素感。
- 现成参考：GDQuest 官方免费教程「2D Tactical RPG Movement」https://www.gdquest.com/tutorial/godot/2d/tactical-rpg-movement/ ；开源框架 https://github.com/ramaureirac/godot-tactical-rpg ；火纹粉丝重制参考 https://github.com/laqieer/FEHR ；B 站中文系列「Godot 4.5 山寨火焰纹章」（BV1g4qcB5ESq）。
- 代价：寻路、AI、伤害公式、转职、支援全要自己写，工期按年计。

**Unity 2D（不推荐零基础）**：官方 Tactics Toolkit 教学包 https://assetstore.unity.com/packages/templates/packs/tactics-toolkit-238215 ；个人版免费（收入<20 万美元），2023 Runtime Fee 风波后已取消该项收费；学习成本偏高。

**RPG Maker + SRPG 插件（能玩但嫁接感强）**：官方 DLC「SRPG Gear MV/MZ」（2025 年仍维护）Steam 页 https://store.steampowered.com/app/2811900/ ；免费社区路线 SRPGcore https://github.com/RyanBram/SRPGcore ；默认 RTP 风格离 GBA 像素较远，不如 SRPG Studio 原生。

**其他（仅练手）**：PICO-8（128×128，承载不了长篇）、LÖVE（无编辑器纯代码）、libGDX/MonoGame（一切手写）、GDevelop（战棋能力弱）。

### 3.3 推荐结论

- **零编程、重剧情、求还原 → SRPG Studio**：不用写一行代码就能搭出转职/克制/支援/多章剧情，官方中文已就位，成品可一键导出 exe。代价：一次性付费 + 战斗逻辑深度改动的上限。
- **想顺便学编程、长期自由发挥、不想花钱 → Godot 4**：免费、教程多，照 GDQuest 教程先复刻移动/攻击/寻路，逐步实现火纹系统。代价：周期按年计。

### 3.4 技能与学习路径（若选 Godot 4）

- 入门（1~3 月）：Godot 界面与节点/场景；GDScript 基础；GDQuest 战棋移动教程；TileMap 画 32×32 地图；240×160 viewport 整数缩放。
- 进阶（3~9 月）：A* 寻路（AStarGrid2D）；移动/攻击范围高亮；伤害公式与命中率（双随机数）；武器克制表（Resource 组织数据）；单位状态机；回合流程。
- 火纹专属系统（9~18 月）：转职与成长率、支援对话与好感、商店/装备/耐久、章节事件脚本、AI 决策、战斗动画与音效。
- 发布：存档、多章节流程、平衡测试、导出 Windows/Web、上架 itch.io/Steam。

## 四、内容管线：剧情 / 美术 / 音乐 / 设计

### 4.1 剧情体量基准

GBA 原版参考（约数，可到 fireemblemwiki.org 复核）：
- FE6《封印之剑》：约 30+ 章（含外传），可玩角色约 54 人，支援对话约 150 对。
- FE7《烈火之剑》：单周目约 31 章（全模式合计 42 章），角色约 44 人，支援约 145 对。
- FE8《圣魔之光石》：主线 22 章 + 双主角分线 + 外传/刷级塔，角色约 33 人，支援 100+ 对。

**给新手的首作规模建议：12~18 章、15~25 名角色、20~40 组支援对话（每组 C/B/A 三段）、单结局。** 文本量估算：主线约 4~6 万词，加支援与战前战后事件约翻倍至 8~10 万词。

参考：章节列表 https://fireemblemwiki.org/wiki/List_of_chapters_in_Fire_Emblem:_The_Binding_Blade ；支援对话 https://serenesforest.net/binding-blade/characters/supports/

### 4.2 像素美术

**原版规格**（GBATEK + 社区教程）：屏幕 240×160；硬件 tile 8×8，火纹地图格 16×16（可视 15×10 格，注意不是 32×32）；调色板 15 色+透明；头像约 96×80、16 色，带眨动/嘴型帧；地图小人 16×16；战斗动画多帧拼装，每职业攻击/回避/暴击/施法 4~6 段、每段 20~40 帧、约 10~15 fps，敌我仅换调色板。**引擎路线不必死守这些数字，重点是统一的比例、限色与轮廓风格。**

- **工具**：Aseprite（约 $19.99 买断，像素画事实标准）https://aseprite.app/ ；LibreSprite（免费开源分叉）；Photoshop 可用但效率低。
- **免费素材**：OpenGameArt https://opengameart.org ；Kenney（CC0）https://kenney.nl ；itch.io 像素包；FE 社区自产素材库 https://github.com/SigmaRaven/FE-Repo ——注意各素材的授权条款，**不要 rip 任天堂原版素材**。
- **工作量**：画齐一套（地图 tile + 约 20 个头像 + 12~15 职业战斗动画 + UI）约 400~600 小时。
- **还原要点**：限色调色板、深色轮廓、抖动过渡、二头身 Q 版比例、敌我双色方案。学习路径：临摹官方截图 → 限色练习 → 16×16 小人 → 头像 → 战斗动画。
- 战斗动画参考：https://fe-battle-animations.neocities.org/ ；动画拆解 https://lost-worlds.neocities.org/blog/2024/10/20/fire-emblem-animation/

### 4.3 音乐

GBA 火纹是 CPU 软混 8bit PCM 采样的"采样交响+电子"混合感。现代做法：DAW + 免费管弦音色（Spitfire LABS、VSCO2）作曲，导出带循环点的 OGG。

- 工具：LMMS（免费 DAW）、Reaper（$60，试用到期不锁功能）、Furnace/FamiTracker（chip 风 tracker，宜做音效与复古段子）。
- 免版权：OpenGameArt 音乐区、Kenney 音频、incompetech（CC-BY）、itch.io 音乐包；AI 生成（Suno/Udio）可做草稿，免费档商用条款需看清当期规则。
- 乐理门槛：和声学入门（三和弦、常用进行）+ 配器常识（弦乐铺底+铜管主奏+打击）即可起步；先写 4~8 小节动机循环再扩展成曲。

### 4.4 游戏设计文档

需要设计的系统：章节结构（主线/外传/分线）、职业与转职树（成长率基值/上限）、武器三角（剑>斧>枪）与魔法三角（理>光>暗）、支援系统（点数积累 + C/B/A 对话 + 战斗加成）、敌军设计（增援点/Boss/掉落）、难度曲线（经验经济、武器耐久、永久死亡开关）。

solo 开发要写的 5 份文档（表格即可承载）：① 一页式设计摘要；② 剧情大纲+章节表（目标/登场/事件）；③ 角色表（成长率/登场章/支援网）；④ 关卡表（地图、敌配置、增援波次）；⑤ 数值表（公式与职业基值）。

## 六、工作量估算与减负建议

- **2~3 人分工**：① 编剧兼关卡设计；② 美术专职（最大瓶颈：头像+战斗动画）；③ 程序兼音乐（音乐也可外包或买包）。
- **纯 solo 做 15 章体量**：美术 40~45%（500h+）、剧情写作 15~20%（约 200h）、关卡与数值 15%（约 180h）、程序 15%（约 180h）、音乐 10%（约 100h）——**合计约 1200~1500 小时：业余 1.5~3 年，全职 6~12 个月**。
- **必须自己做**：剧情与角色设定（差异化核心）、头像（辨识度与风格统一）、数值与关卡设计（可玩性核心）、Logo/主视觉。
- **可买/可找**：地图 tile（OpenGameArt/LPC、itch.io 包）、UI 与特效、音乐与音效、通用图标。
- **减负折中**：战斗动画先做 4~6 个核心职业、其余复用帧；支援对话砍到 20 组内；音乐 10~12 首按情绪分组复用。

## 七、版权注意事项

- **改版路线**：不得分发 ROM，只发补丁（.ups/.bps）；不商用、低调发布。虽然任天堂没有官方许可，但社区 20 年惯例下风险较低。
- **引擎原创路线**：素材必须自产或使用明确免费/授权素材（OpenGameArt、itch.io 的 CC0/CC-BY 包等），**不要直接扒火纹原版立绘、头像、战斗动画、音乐**——那同样构成侵权，只是换了外壳。
- 角色名、世界观、剧本尽量原创；"致敬玩法机制"（网格战棋、武器克制、转职、支援对话这些玩法本身）不受版权保护，可以放心做。

## 八、下一步建议

1. **先定路线**：A（GBA 改版，FEBuilderGBA）还是 B（引擎原创，SRPG Studio / Godot），以及目标平台（模拟器 / PC / Web / 手机）。
2. **先写一页设计摘要 + 剧情大纲**（1~2 周），再动手做 3~5 章 demo，验证手感与自己的工期承受力。
3. 路线 A 起步：装 FEBuilderGBA → 跟中文 wiki + B 站教程，先复刻原版一章关卡练手。
4. 路线 B（SRPG Studio）起步：Steam 入本体（常打折）→ 跟教程搭一章战斗 → 逐步换 GBA 风素材。
5. 美术先全部用免费素材占位，边做边替换成自制；剧情先写完 12~18 章大纲再逐章扩写。

> 补充（2026-09-24）：首作规模已定为 **3~5 章 demo 试水**；路线待用户在第九节判据清单中拍板。

## 九、路线体验展开对比（帮你拍板）

### 9.1 画面观感

- **路线 A**：就是原版 GBA 像素本身——UI、头像、战斗动画逐像素同源；模拟器整数缩放/滤镜/60 帧后更顺眼。知名改版（Vision Quest、Reforged、圣邪的意志）观感 = 原版。
- **路线 B**：SRPG Studio 默认不是纯 GBA 像素风（维斯塔利亚传说 = 现代日系立绘 + 复古地图的混搭，见 https://techraptor.net/gaming/reviews/vestaria-saga-i-war-of-scions-review ）；但素材可全部替换（官方素材手册 http://www.srpgstudio.com/help/material.html ），低分辨率+整数缩放、16×16 tile 放大 2 倍可做成像素风，有《卡琳的尤格多拉尔战纪》(Karin's War) 作证（B 站发布视频 https://www.bilibili.com/video/BV1BaPBegEiA/ ）。Godot 则完全可控：240×160 viewport + 整数缩放 + 16 色调色板即可复刻观感。

**结论：A 还原度 100% 且零成本；B 能还原到"像素味"，但靠素材投入。**

### 9.2 战斗动画手感

- **A**：原版/社区手绘逐帧、打击感干脆；社区有成熟教程站（https://fe-battle-animations.neocities.org/ ）和 AAA 动画制作工具（https://github.com/Benst1996/AAA ），自制动画插回 ROM 流程成熟。
- **B**：SRPG Studio 默认是**地图上直接演出**（冲上去砍+特效，无独立战斗画面），可替换为自制像素动画（官方教程 http://www.srpgstudio.com/lecture/motion.html ）但还原度与工程量自己扛；Godot 则战斗演出从零做。

**结论：如果"战斗动画"是情怀核心，A 优势明显。**

### 9.3 发布方式与玩家

- **A**：只发补丁，玩家用 mGBA / RetroArch / 安卓模拟器 / 开源掌机（Batocera）/ 烧录卡玩；受众 = 火纹核心粉、模拟器党；**无法上架售卖**。
- **B**：可导出 exe，上 itch.io / Steam；受众 = 普通 PC 玩家、独立游戏玩家；素材合规前提下**可以卖钱**。

### 9.4 换路线成本（重要：美术投资两条路都能带走）

- **A→B 可搬**：头像、tile、战斗帧都是普通 PNG，现代引擎直接吃；16 色调色板完全兼容（限制只存在于 GBA 侧）；关键是整数倍缩放保持锐利（16×16 tile 放大 2 倍即可）。
- **B→A 难**：引擎里的无限色/大画布素材要压回 16 色索引、改尺寸、按 FEGBA 格式重排动画（AAA 工具），等于重做。
- 剧情**纯文本两边通用**；**不可移植**的是 FEBuilder 事件脚本、数值表/职业成长结构和 Godot 的 GDScript 逻辑。
- **推论：拿不定主意时，先按 A 的规格（16 色、16×16 tile）做美术，最后无论选哪条路，素材都不浪费。**

### 9.5 判据清单

| 你的情况 | 选择 |
|---|---|
| 想上架卖钱 | B（素材合规前提下） |
| 只想免费分享给同好 | A |
| 要求 100% 原版观感（UI/头像/动画逐像素还原） | A |
| 接受"像素味但不完全原版" | B |
| 完全不想碰代码/脚本 | A 或 SRPG Studio |
| 愿意学编程（GDScript） | Godot |
| 目标玩家是火纹核心粉/模拟器党 | A |
| 目标玩家是普通 PC 玩家/独立游戏受众 | B |
| 想在火纹规则内讲好一个自己的故事 | A |
| 想自创职业/系统/世界观框架 | B |
| 预算 | A≈0；SRPG Studio 一次性买断（常打折）；Godot 免费但时间成本最高 |

**结合你的选择（3~5 章 demo 试水）**：两条路都能在 3~6 个月内做出 demo。若你的情怀核心是"原汁原味的 GBA 画面与战斗动画"，且接受只发补丁 → 选 A；若你更在意"合法、将来可能发布/售卖" → 选 B（SRPG Studio，美术仍按 16 色规格做，日后也不浪费）。

## 十一、路线决策结论（2026-09-24 已拍板）

> 用户明确四项前提：**① 不卖钱（纯爱好）② 尽量还原原版画风 ③ 自己是程序员，会写代码 ④ 想借此学习**。

### 11.1 最终选择：路线 A+ —— FE8 反汇编扩展框架

选定 **`laqieer/fireemblem8-expansion`**：基于 fireemblem8u 反汇编，以现代 `arm-none-eabi` GCC 从 C/ASM 源码构建 ROM。

| 备选 | 还原度 | 结论与理由 |
|---|---|---|
| **FE8 反汇编扩展框架** | **100%** | ✅ **采纳**——四项前提全部满足；且大量 v0.5 中"必须自研"的系统（战斗预测/危险范围/物品栏/仓库/出击整备/支援框架/转职树/战斗动画）**在原版中已存在**，直接消灭约一半工作量 |
| FEBuilderGBA 改版 | 100% | ❌ 放弃——在成品 ROM 上打洞，改逻辑自由度低；无法满足"程序员想学底层"的诉求 |
| SRPG Studio | ~85% | ❌ 放弃——免编程是卖点，对程序员是缺点；战斗演出偏弱 |
| Godot 4 自研 | 可控（但需自建一切） | ❌ 放弃——"还原画风"的成本是数量级差距；每一像素、每个系统都要自己重建 |

### 11.2 关键判断依据

1. **画风还原的成本不是线性差距，是数量级差距。** GBA 火纹的观感有相当部分藏在硬件约束里（15 色 + 1 透明、8×8 硬件 tile、240×160、CPU 软混音频）。在现代引擎里要还原，得主动给自己绑 GBA 的镣铐，且**没有任何工具帮你绑**。而在 FE8 框架里，资产就是原版资产。
2. **战斗动画是最大时间黑洞**（原报告 §6 估算美术占 40~45%）。改版路线下这部分**归零**；Godot 路线下是 100% 自己扛。
3. **该框架不需要原版 ROM 即可构建**——开发环境干净、可 CI，对程序员是正常的工程方式。
4. **简体中文是官方一等公民**：命名构建目标 `make expansion-modern-localization-profile-en-zh-hans` 直接出中文 ROM，3,414 条游戏消息全量覆盖，有逐行宽度校验与运行时 CJK 门禁。（代价：中文必须 `MODERN_ROM_SIZE=32M`）
5. **数据管线对程序员友好**：`src/data/*.json` + 统一的三动词 `validate / generate / check`，跨表引用悬空立即报错；本项目数值文档的表几乎可一一映射进去。

### 11.3 这条路的代价（已知并接受）

- 只能在 GBA 硬件约束内做（EWRAM 256KB / IWRAM 32KB 预算紧张）
- 学习曲线陡：Proc 协程系统、ARM 汇编、GBA 硬件寄存器
- 官方只支持 Ubuntu / WSL / Arch / macOS，**Windows 需走 WSL2**
- 成品靠模拟器玩，不能上架——但用户明确不卖钱

- 技术路线与系统设计：`2.设计文档.md` §1/§6/§7/§11/§12
- 环境搭建与工程操作：`5.改版工程手册.md`
- 改造清单（原版够用 vs 必须改）：`2.设计文档.md` §11

### 11.5 最高优先级待验证风险

**中文字库容量**。框架的 CJK 字体页按字频取舍，示例规模有限；20 章剧本文本量可能超出。**P0 必须实测**容量上限、多页扩展可行性、32M 空间预算。
