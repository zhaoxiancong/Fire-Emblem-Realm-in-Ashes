## 0. 目标与范围

- **目标**：一部约 20 章完整故事线、单线推进的原创世界观 SRPG，玩法与观感致敬 GBA 火焰纹章。**画风按 100% 还原原版为目标**——这是本项目的核心诉求，也是技术路线选择的唯一决定性因素。
- **游戏名**：**《山河烬》**（已拍板；同名检索无商业游戏冲突）。**英文名（暂定）**：*Realm in Ashes*。
- **成功标准**：完整可通关 20 章；玩家（自己 + 同好）评价"和原版火纹一个味"。
- **发布**：**免费分享给同好，不卖钱**；分发形式 = **补丁（.ups/.bps）+ 打补丁说明**，玩家用 mGBA / RetroArch / 安卓模拟器 / 开源掌机游玩。
- **v1 明确不做**：联网对战、商业化、多语言（先中文）、多周目差分、移动端原生 App。
- **体量红线（待拍板）**：20 章为目标体量；**12~15 章为可接受缩水线**（砍掉部分中幕章节、外传优先保留），在 P3 demo 决策门时按实际产出速度再评估——solo 开发防止"全或无"烂尾。

## 2. 核心玩法

- **网格**：地图格 16×16 像素，可视 15×10 格；地形移动力消耗——**原版规格，无需设计**。
- **回合**：玩家回合 / 敌方回合——**原版规则**。
- **战斗公式**：以 **`3.游戏数值设定.md` 第 1 节为唯一来源**。实现落位于原版战斗代码（`src/`，见 §12）；2RN 判定、追击阈值均为原版行为，**改造时须显式决定"是否保留原版"**（见 §11 改造清单）。
- **克制关系（本项目原创，需改写原版）**：
  - **兵刃三环**：枪 → 刀 → 锤 → 枪；**剑不入环**（中立生态位，主角/剑客系）；
  - **三才法环**：天克地、地克人、人克天；
  - 弓、弩在环外；克制标签只对攻击类法术生效。
  - **实现方式**：原版武器三角为"剑→斧→枪"单一环，本项目需要**双环 + 环外特例**——这是必须改代码的第一处（`src/data/` 有武器三角机制表，配合 `include/expansion_mechanics.h`）。
- **敌方 AI**：原版已有完整的 AI 框架（进攻/驻守/逃跑/治疗/盗贼开箱）。
  - v1：沿用原版 AI + 调整权重（可击杀 > 伤害期望 > 命中率）；
  - v2（P4）：细化护送目标保护权重、凶相专属行为。
- **战场信息 UX**：战斗预测面板 / 危险范围 / 单位详情 —— **原版全部已有**，仅需：① 确认中文文本渲染正确；② 确认三环克制修正能显示在预测面板中。
- **悔棋（可选增强）**：原版无"回溯"，但有**每回合自动存档**（`SUSPEND`）。方案二选一：① 依赖模拟器即时存档（推荐，零成本）；② 在机制钩子中实现快照回溯（成本中等，收益低）。
- **经验与成长**：个人成长率 + 职业成长加成——**原版系统**。随机/固定成长切换通过机制钩子实现。
- **转职**：`classes.json` 的 `base`/`max`/`growth`/`promotionGain` 字段原生支持 1~3 阶与分支。
- **神器系统**：9 件神器（圣皇铸鼎余料）。规则与数值见数值文档第 3 节；特效 = 专属配色 + 粒子层。**原版道具上限为 `0xCE`，扩展道具需 `--enable-mechanics-hooks` + 提升 item cap。**
- **说得系统**：原版已有"说得"指令（`Talk`），复用即可；第 3 章郡丞卫队长为首个用例。
- **支援与感情线**：义理值四档（陌路→相识→相知→生死之交）→ 映射到原版支援 C/B/A；战斗加成见数值文档第 8 节。**`supports.json` 要求支援关系必须双向**（框架强制校验）。
- **物品栏与仓库**：**原版内置**（5 格 + 运输队 100 格）。
- **出击与整备**：**原版内置**（整备界面选人/换装/商店/查看）。
- **商店/装备/耐久**：**原版系统**；神器走"黯淡 + 龙髓/铁匠铺"独立规则（需新增）。
- **存档**：**原版系统**（3 槽 + 中断档）；框架已扩展 `ExpansionUserPrefs`（0x0C 字节 SRAM 记录）用于语言等偏好。

## 3. 章节结构

- **五幕 20 章**（结构详见世界观圣经第 4 节）：一·故乡失火（序~4）→ 二·帝都迷局（5~7）→ 三·北地真相（8~12）→ 四·会盟天下（13~16）→ 五·归墟决战（17~20）+ 外传 2 个（白鹤观旧事 / 幽都判官）。
- 每章流程：开场剧情（史书体旁白）→ 战前情报 + 整备 → 战斗 → 战后剧情。**原版事件脚本框架原生支持此流程。**
- 胜利条件类型：全灭 / 护送 / 防守 N 回合 / 占旗压制 / 限时 / 攻城 / BOSS 击退。
  - **框架原生支持的目标类型**（`chapter_objectives.json`）：`reach_area`、`defeat_group`、`protect`、`hold_until_turn`、`event_flag`；
  - **需扩展的**：占旗压制、限时、攻城 —— 可用 `event_flag` + 事件脚本组合实现；
  - 每章上限 8 个 objectives、8 个 AI 组、每组最多 16 个成员（**框架硬约束**）。
- **事件触发器**：**直接用原版事件脚本体系**（`eventscripts.json` / `eventlists.json` + Event Assembler 语法）。原版已支持回合数、区域进入、单位死亡、村庄访问、说得、战斗对话等全部触发器，**无需自研 EventRunner**。
- **Demo = 序章~第 4 章（5 关）**，完整跑通全部系统后作为决策门验收；关卡配置见 `4.关卡表_Demo五章.md`。
- **教程策略**：序章强制教学（移动/攻击/克制/护送）；新机制首次出现弹提示卡。**原版无此机制，需新增**（用事件脚本 + 消息文本实现，成本低）。
- **章节数据落位**：每章一个 `src/data/chN_*.json` 捆绑（`units` / `shops` / `traps` / `eventscripts` / `eventlists` / `bundle`），见 §12。

- **原版切屏战斗动画直接复用**——这是本路线最大的减负项。
- 演出脚本（进场 → 攻击 → 命中闪光 + hitstop + 震屏 → 伤害数字 → HP 条 → 退场）**全部是原版现成实现**。

## 5. 美术与音频规格

- **分辨率/调色板/格尺寸**：240×160、15 色 + 1 透明、16×16 地图格、8×8 硬件 tile —— **原版规格，不需要设计**。
- **头像**：原版 96×80、16 色，含眨眼/口型帧。原创角色头像需自画（Aseprite）。
- **中文字体（v0.6 方案）**：
  - 走框架官方 CJK 本地化：文本放 `texts/locales/zh-Hans/indexed.txt`（3,414 条游戏消息）与 `texts/expansion/catalog.zh-Hans.json`（扩展 UI）；
  - 字体页由构建系统**确定性生成**：统计 U+4E00–U+9FFF 字频，按频次降序取字，13px cell pitch；
  - 有**逐行宽度校验**（`make localization-... check-width`）和运行时 CJK 门禁；
  - **硬约束**：中文版必须 `MODERN_ROM_SIZE=32M`（16M 会在编译前失败）；
  - **不再需要** v0.5 的"正文全走屏幕空间 UI 层"铁律——因为不需要自研 UI 层，直接用原版对话框体系。
- **音频**：**GBA 音频引擎（CPU 软混 8bit PCM）**，格式为歌曲表 + 音轨。
  - 原版 BGM 可直接复用作为占位；
  - 替换方法：**ELF 方法**（免 Sappy）https://feuniverse.us/t/music-hacking-the-elf-method-no-sappy-2006/102 ；
  - 作曲工具：LMMS / Reaper + 免费管弦音色；chip 风可用 Furnace；
  - demo 目标：8 首原创 BGM 按情绪复用 + 2 个 jingle。
- **授权原则**：**本项目不涉及第三方素材授权问题**——只使用原版资产（自用、免费分享、不发 ROM 只发补丁）与自画素材。
- **触摸 UI 适配**：**不再需要**（v0.5 的触摸层/InputRouter/48px 触摸目标设计全部作废）。操作走 GBA 原生按键，模拟器提供虚拟按键。

### 5.1 中文字库容量（需要验证的风险）

框架的 CJK 字体页按字频取前 150 个标量（两页 75 格）——这是**示例规模**，真实项目 20 章剧本文本量远超此数。**P0 必须验证**：实际字库容量上限、是否可扩展多页、以及 32M 空间是否足够容纳 20 章全部中文文本 + 原创头像。这是 v0.6 引入的**最高优先级技术风险**。

## 6. 技术架构（FE8 扩展框架）

- **基底**：`laqieer/fireemblem8-expansion`（基于 fireemblem8u 反汇编，MIT 风格开源），以现代 `arm-none-eabi` GCC 工具链从源码构建 ROM。
- **不需要原版 ROM 即可构建**（原版 ROM 仅用于反汇编比对 `asmdiff.sh`）。
- **开发环境（Windows 用户必读）**：
  - 官方自动安装脚本仅支持 **Ubuntu / WSL / Arch / macOS**；
  - **WSL2 (Ubuntu) 是 Windows 下的推荐且事实唯一路径**；
  - 仓库须放在 WSL 文件系统内（`~/`），**不要放 `/mnt/d/`**（跨文件系统会极慢）；
  - 磁盘约 2.5 GB，首次完整构建最长约 15 分钟。
- **构建产物**：`build/expansion-modern/release/aapcs/fireemblem8.gba`；另有 `.elf`（带调试符号）、`.map`（链接器映射）。
- **数据驱动层**（**这是日常改内容的主战场**）：
  - 所有内容用 JSON 写在 `src/data/` 下；
  - 三个统一动词：`validate`（校验）/ `generate`（生成 C89）/ `check`（漂移门禁，CI 用）；
  - 跨表引用用符号（`CHARACTER_*` / `CLASS_*` / `ITEM_*` / `MSG_*` / `EVFLAG_*`），悬空引用立即报错并给出 `file:line:column`；
  - **绝不手工编辑 `build/generated/data/` 下的生成代码**。
- **代码层**：`src/` 下的 C 与 ARM 汇编；`include/expansion_mechanics.h` 提供带容量约束的战斗属性注册表（回调收到可变攻击者 + 只读防御者上下文）。
- **本地化层**：`src/expansion_locale.c` 提供 `ExpansionLocale_GetCurrent/_SetCurrent/_Resolve/_InvalidateCache`，与原生 `GetLang()` 完全独立。
- **测试框架**：`tools/gba-playtest/` 用 libmGBA 回放 JSON 场景并比对逐帧指纹；`make expansion-modern-boot-check` 在帧 0/60/120 验证；`make expansion-modern-linker-check` 做预算漂移与 overlay 审计。
- **调试工具**：ARM GDB 远程调试（`make expansion-modern-gdb-smoke`）、mGBA GDB server、五个有界调试工具（单位/运输队/旗标/RNG/存档状态）、结构化探针与日志环。
- **参考文档**：`docs/README.md`（文档索引）、`docs/architecture.md`、`docs/generated_data_tutorial.md`、`docs/localization.md`、`docs/quickstart.md`。

## 8. 风险与对策（v0.6 重写）

| 风险 | 对策 |
|---|---|
| **中文字库容量不足（v0.6 新增，最高优先级）** | 框架 CJK 字体页按字频取舍，20 章文本量可能超出；**P0 必须实测容量上限与多页扩展可行性**；若不足，备选方案 = 精简用字表 + 替换用频次更高的字 |
| **GBA 内存预算紧张（v0.6 新增）** | EWRAM/IWRAM 余量固定（IWRAM 栈余量仅约 0x1000 字节门禁）；新增系统须在 `make expansion-modern-linker-check` 下验证预算；**大量新内容可能需要 32M ROM 与精心规划 bank** |
| **原版战斗代码改造引入 bug（v0.6 新增）** | 三环克制、神器机制均需改原版逻辑；**必须用框架的回放测试框架建立回归基线**，每次改动跑 `boot-check` + 相关场景指纹 |
| **学习曲线陡（v0.6 新增）** | Proc 协程系统、ARM 汇编、GBA 硬件寄存器均需学习；对策 = 先改数据（JSON）后改代码（C）最后碰汇编，分阶段推进；框架文档齐全 |
| **WSL 环境门槛（v0.6 新增）** | 官方不支持原生 Windows；对策 = 按 §6 用 WSL2 并把仓库放 WSL 内；VS Code + WSL 扩展开发体验良好 |
| **20 章烂尾** | 单线结构；章节数据化管线；P3 demo 决策门；**体量红线 12~15 章缩水预案（待拍板）** |
| 原创头像美术量 | 22 名角色头像；对策 = 原版头像改色/改发型派生优先，仅主角 + 2~3 关键角色全新绘制；Aseprite |
| 原创战斗动画美术量 | 优先映射到原版职业骨架 + 调色板派生；仅主角系可能需要新画；AAA 工具链成熟 |
| **写作量爆炸** | 总预算主线 4~6 万字 + 支援先 13 组核心（世界观圣经 5 节已排优先级）；超支则砍支援组数不动主线 |
| **文档间引用漂移** | 四件套单一来源：系统意图看本文档、故事看世界观圣经、**数字一律看数值文档**、工程操作看改版工程手册；每里程碑收尾同步刷新 |

> **已消失的风险（v0.5 有、v0.6 无）**：战斗动画从零做（原版资产复用）、Godot 中文字体坑（官方方案）、中文 UI 信息密度危机（原版对话框体系）、永久死亡×手机误触（模拟器即时存档兜底）、触摸误触/按钮太小（无触摸层）、安卓设备碎片化（模拟器统一）、APK 侧载门槛（改发补丁）、素材授权风险（只用原版资产 + 自画）。

### 10.2 v0.6 路线转向记录

> 2026-09-24 用户明确四项前提：**① 不卖钱（纯爱好）② 尽量还原原版画风 ③ 自己是程序员，会写代码 ④ 想借此学习**。据此重新评估技术路线。

| 备选 | 还原度 | 结论 |
|---|---|---|
| **FE8 反汇编扩展框架** | **100%**（原版资产原生复用） | ✅ **采纳**——四项前提全部满足；且消灭 v0.5 中约一半的"自研系统"工作量 |
| FEBuilderGBA 改版 | 100% | ❌ 放弃——是在成品 ROM 上打洞，改逻辑自由度低；无法满足"程序员想学底层"的诉求 |
| SRPG Studio | ~85% | ❌ 放弃——免编程是它的卖点，对程序员是缺点；战斗演出偏弱 |
| Godot 4 自研 | 可控（但需自建一切） | ❌ 放弃——"还原画风"的成本是数量级的；v0.5 选它是因为当时未确认"会写代码 + 不卖钱" |

**关键澄清（v0.5 的一个误判）**：v0.5 认为"战斗演出必须自研、美术 150~250 小时"。在 FE8 框架下，战斗动画、UI、头像、tile **全部是现成资产**，这部分成本归零。真正的成本转移到：中文文本录入、原创头像绘制、原创剧情事件脚本、以及**理解并改造原版代码的学习成本**。
