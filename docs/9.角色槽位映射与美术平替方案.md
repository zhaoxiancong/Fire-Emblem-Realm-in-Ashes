## 1. ★ 核心洞察：三层美术资源绑在不同对象上

这是理解"平替"的钥匙。框架里的美术资源分三层，**绑定对象各不相同**：

| 资源层 | 绑定对象 | 数据结构 / 位置 | ID 空间 | 规模（实测） | 替换成本 |
|---|---|---|---|---|---|
| **立绘 / 小头像** | **角色** | `characters.json` 的 `portrait` 字段 → `assets/portrait_registry.json` `entries[]` → `src/face.c` | `1..0xAC`（172，已满）+ `0x7F00..0x7F07`（8 杂兵） | 172 条注册 / 1,038 个 PNG | **中**（22 套原创立绘，最大工作量） |
| **战斗动画** | **职业** | `classes.json` 的 `battleAnim` → `AnimConf_N` → `src/data_banimconf.c` 的 `{wtype, index}` → banim 资源 | 101 个 `AnimConf_N` | **2,491 个文件**（`graphics/banim/`） | **最高**（Manual-only，官方称单位成本最高） |
| **地图小人 / 单位图标** | **职业** | `src/unit_icon_wait_data.c` 的 `unit_icon_wait_table[]`，由 `src/bmudisp.c:345` 索引 | **7 位（0..127）** | 107 条 | **低**（换 4bpp 图） |
| **武器 / 道具图标** | **物品** | `graphics/item_icon/`，按物品符号命名 | 物品 ID 空间 | — | **低**（复用 + 改色） |

**由此推出的三条操作结论：**

1. **改职业 = 自动换掉战斗动画 + 地图小人。** 你不需要为"换动画"做任何额外登记——职业一改，动画和图标跟着走。
2. **改角色 = 只换立绘。** 立绘是唯一"跟角色走"的美术资源。
3. **所以"模型平替"的工作量 = 22 套立绘 +（可选）若干职业动画。** 而不是 22 套动画。

> **一句话**：**把 22 个原创角色塞进原版职业，你就免费得到了 22 套战斗动画和地图小人。** 后期要"换皮"，只需换立绘（角色级），动画可以一直复用下去。

## 2. 原版底数（实测）

### 2.1 可玩角色：33 人

`src/data/characters.json` 共 **256 条**记录，但绝大多数是无名占位（只有 `defaultClass`、没有 `character` 符号），是给关卡临时单位/BOSS 用的模板位。

**可靠判据**：真正"可玩 + 有支援系统"的角色都有 `supportData` 字段。实测结果：

```
有 supportData 的记录 = 33 条
```

这 33 人即《圣魔之光石》双路线合计全部可招募角色。

### 2.2 职业：127 条 / 动画配置 101 个

`src/data/classes.json` 共 **127 个职业**，每条含：
- `promotion`（转职目标）
- `baseRanks`（初始武器熟练，即武器系）
- `battleAnim`（战斗动画配置 `AnimConf_N`）
- `defaultPortraitId`（职业默认立绘，用于无专属立绘的单位）
- `attributes`（`MOUNTED`/`FLYING`/`PROMOTED`/`CRITBONUS` 等）

**关键**：`battleAnim` 是**职业级**的唯一动画入口。例：

```c
// src/data_banimconf.c
CONST_DATA struct BattleAnimDef AnimConf_1[] = {   // 艾莉卡的剑动画
    { .wtype = 0x0100 | ITYPE_SWORD, .index = 0x0003 },
    { .wtype = 0x0100 | ITYPE_ITEM,  .index = 0x0004 },
    { 0 }
};
```

即：一个 `AnimConf_N` = 一组「武器类型 → 动画资源序号」映射。

> **注意**：主角有**专属职业**（`CLASS_EIRIKA_LORD`），因此也有专属动画。普通剑士用 `CLASS_MYRMIDON`（另一套动画）。这是"主角演出更华丽"的机制来源。

### 2.3 立绘槽：172 条，已满

`assets/portrait_registry.json` 的结构是 `{ schemaVersion, entries[] }`，**恰好 172 条**，ID 精确覆盖 `1..172`，**零缺口**。

但 `characters.json` 只显式引用了其中 **67 个** ID（范围 `2..105`）。差额 105 个槽位由 `ch*_bundle.json`（章节内临时角色）、可说得角色、剧情 NPC 等占用。

**结论：没有空闲立绘槽可以白拿。** 22 名原创角色必须**替换**（覆盖）现有槽位。

**这不构成问题**，理由：
- 原版 33 个 PC 槽中有 11 个我们暂不使用（见 §3.4），可先占用；
- 即使覆盖的是原版主角立绘，由于我们**全部剧情重写**，原版角色不会再出现在游戏里——被覆盖的立绘本来也不会被看到。

### 2.4 地图小人：107 条，7 位 ID

```c
// src/bmudisp.c:345
#define GetInfo(id) (unit_icon_wait_table[(id) & ((1<<7)-1)])
```

`unit_icon_wait_table[]` 定义在 `src/unit_icon_wait_data.c`，**107 个条目**，索引空间被 **7 位掩码**（`0..127`）限制。资源分两套：`graphics/unit_icon/move/`（移动动画）与 `graphics/unit_icon/wait/`（待机），另有 5 个调色板（`player`/`enemy`/`npc`/`p4`/`after_action`）用于阵营换色。

> **重要**：这是**独立于立绘的第二套 ID 空间**。即使立绘改了，地图小人仍由职业决定。阵营配色（我方蓝/敌方红/友军绿）由调色板自动处理，**同一个职业图标复用给敌我双方**。

### 2.5 战斗动画资源规模

`graphics/banim/` 下 **2,491 个文件**——每个"职业 × 武器"组合一套（含帧图、TSA、调色板、`.lz` 压缩产物）。这是框架里**最大、最贵**的美术资产池。

**这也是"尽量复用"的最强理由**：原创 22 套战斗动画的成本，量级上等于重做一个中型项目的美术。

### 3.3 高分匹配的三处亮点

- **虞聪 ↔ 艾莉卡、秦红缨 ↔ 艾夫拉姆**：原版**双主角各占一条武器线**（剑 / 枪），而《山河烬》双主角（男女主）恰好也是剑 / 枪之外的组合……**更妙的是**：原版两个 `LORD` 职业都有**专属动画 + 专属剧情演出位**。虞聪用艾莉卡槽 = 白得一套主角级剑演出。

**对策（按推荐度）**：
1. **换职业变体**：柳青鸾用 `CLASS_MYRMIDON_F`（女剑士）承载"飞贼"——武器系一致（剑/短刀），地图小人是女性形象。**推荐**。
2. **接受男性小人**：盗贼的地图小人视觉上并不强调性别，可先接受，后期再评估。
3. **新建 `CLASS_THIEF_F`**：需要新的单位图标 ID（7 位空间还剩 20 个左右）+ 一套 banim。**成本高，不建议 Demo 期做**。

> **反向情况**：飞马、天马骑士、修女（`CLERIC`）、骑马修女（`TROUBADOUR`）、舞娘、龙人**只有女性版本**。我们对应的原创角色（姬瑶、阿蘅、沈婉莹、胡九儿）恰好都是女性，无冲突。

### 4.2 武器系映射：原创武器要落到原版武器系

原版武器系只有：**剑 / 枪 / 斧 / 弓 / 理 / 光 / 暗 / 杖**（+ 特殊）。而《山河烬》设计了 **剑 / 刀 / 枪 / 锤 / 弓 / 弩 / 短刀 / 法器等**。映射关系：

| 原创武器系 | 落到原版 | 说明 |
|---|---|---|
| 剑 | `ITYPE_SWORD` | 直接对应 |
| **刀** | `ITYPE_SWORD` 或 `ITYPE_AXE` | 原版无刀。**建议先落 `SWORD`**（贴"百兵之君"的中立生态位） |
| 枪 | `ITYPE_LANCE` | 直接对应 |
| **锤** | `ITYPE_AXE` | 原版无锤。斧系动画最接近（重武器挥砸） |
| 弓 | `ITYPE_BOW` | 直接对应 |
| **弩** | `ITYPE_BOW` | 复用弓动画，但缺"弩"的视觉区分（见 §3.4） |
| **短刀** | `ITYPE_SWORD` | 复用剑动画 |
| **法器（天道）** | `ITYPE_ANIMA`（理） | 雷法 ≈ 理魔法 |
| **法器（地脉）** | `ITYPE_DARK`（暗） | 巫蛊 ≈ 暗魔法 |
| **法器（人和）** | `ITYPE_LIGHT`（光） | 礼乐 ≈ 光魔法 |
| 医药 | `ITYPE_STAFF` | 直接对应 |
| 兽灵 | — | 无对应，走变身机制（复用龙人） |

> **与"兵刃三环"的关系**：原版武器三角是「剑→斧→枪→剑」。我们要改成「枪→刀→锤→枪，剑中立」。**Demo 期建议先保留原版三角**（零成本），等数值阶段再改 `weapontriangle.json`（该文件是纯数据驱动，见 `6.方案B内容外置规划.md` §5）。

## 5. 槽位替换的三种做法（对比）

"替换槽位"到底替换了什么？有三种粒度，成本递增：

| 做法 | 具体操作 | 保留了什么 | 成本 | 适用阶段 |
|---|---|---|---|---|
| **A. 只换数据 + 立绘** | 改 `characters.json`：`nameTextId`（改名）、`base`/`growth`（改数值）、`portrait`（换立绘）。职业**不动**。 | 原版职业的全部动画、图标、演出 | **极低** | **Demo 期（推荐）** |
| **B. 换职业** | 在 A 基础上，把 `defaultClass` 改成本项目的职业定义（如 `CLASS_SHANHE_SPEARMAN`），但**复用原版动画配置**（`battleAnim` 指向同一个 `AnimConf_N`） | 动画资源（借用），其余自有 | 中 | 中期（要做原创职业时） |
| **C. 全新职业 + 新动画** | 新建职业 + 新建 `AnimConf_N` + 绘制 banim 资源 | 全自有 | **高** | 后期（美术预算到位时） |

**关键技巧（做法 B）**：新建职业时，`battleAnim` 字段可以**直接指向原版已有的 `AnimConf_N`**。也就是说：

> **你可以在数据层拥有"完全原创的职业"，同时在美术层继续借用原版动画。** 两者解耦。

这意味着**"职业动画平替"可以无限期推迟**，甚至永远不做——除非你决定给某个职业做专属动画。

## 6. 分阶段实施路径

| 阶段 | 目标 | 动作 | 美术成本 |
|---|---|---|---|
| **Demo 期**<br>（现在） | 剧情 + 地图跑通 | ① 按 §3.2 矩阵占用 22 个槽位<br>② 只改 `characters.json` 的**名字 / 数值**，职业与立绘**全用原版**<br>③ 武器图标全用原版 | **零** |
| **中前期** | 立绘平替 | 逐套制作 22 个原创立绘包（六帧网格，见文档 8 §3.4），按槽位替换 | 22 套（最大支出） |
| **中期** | 职业自有化 | 做法 B：新建原创职业，`battleAnim` 仍借原版 | 低（纯数据） |
| **后期（可选）** | 动画专属化 | 做法 C：只给主角 + 关键反派做原创 banim | 高，按需 |

**Demo 期验收标准（零美术成本）**：
- 22 个原创角色名字、数值、支援关系在游戏内正确显示
- 序章~第 4 章剧情可完整游玩
- 战斗动画、地图小人、立绘均为原版（**符合预期，不是 bug**）

> **反直觉但重要**：Demo 期"角色长得像原版"**不是缺陷**。原版角色不会再出现（剧情全重写），玩家感受到的是"新角色 + 正统火纹画风"。这恰好是选 FE8 框架的初衷。
